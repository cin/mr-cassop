# mr-cassop

Kubernetes operator for Apache Cassandra (Cassandra 5.x, JDK 17). The `CassandraCluster` CR drives
a StatefulSet per DC, plus a Prober, Reaper, Icarus (backup/restore sidecar), Jolokia and an optional
nodetool UI. Module path `github.com/cin/mr-cassop`, Go 1.26.

Read these first; this file only adds what they don't say:
[CONTRIBUTING.md](CONTRIBUTING.md), [REVIEW.md](REVIEW.md) (Go review rules, enforced in review),
[docs/docs/development.md](docs/docs/development.md), [DOCKER_BUILD.md](DOCKER_BUILD.md).

## Layout

- `api/v1alpha1/` CRD types (`CassandraCluster`, `CassandraBackup`, `CassandraRestore`). Edit types, then `make generate manifests`.
- `controllers/` the operator. Sub-packages: `nodectl` (JMX via Jolokia), `cql`, `prober`, `reaper`, `icarus` clients, `labels`, `names`, `certs`, `webhooks`, `cassandrabackup`, `cassandrarestore`. `controllers/mocks/` is generated (mockgen), never hand-edit.
- `prober/` and `ui/` are **separate Go modules** (own `go.mod`). Root `go build/test/vet ./...` does not cover them; `cd` into them (the Makefile does).
- `mr-cassop/` Helm chart (CRDs in `mr-cassop/crds`, ClusterRole in `templates/clusterrole.yaml` are generated by `make manifests`). `Chart.yaml` version is deliberately stale; the release workflow overrides it from the git tag.
- `cassandra/`, `jolokia/`, `icarus/` image Dockerfiles. `icarus/` builds the jar from the `cin/icarus` fork tag (`ICARUS_VERSION`), bumped in `icarus/Dockerfile`, `release.yml` and `pull_request.yml` together.
- `tests/integration` (envtest), `tests/e2e` (needs a real cluster). `docs/` is a Docusaurus site.
- `.claude/skills/`: `local-install` (build/load/install on the kind cluster) and `cassandra-stress` (load tests). Prefer these over ad-hoc steps.

## Build, test, lint

```bash
make generate manifests fmt vet      # after API/RBAC/mocked-interface changes
make unit-tests                      # controllers + prober + ui
make integration-tests               # envtest; ~6 min
./build-local.sh --cassandra         # operator+prober+cassandra images (VERSION=dev default)
```

- **Never run `go test ./...` at the repo root.** It includes `tests/e2e`, which creates resources in whatever cluster `kubectl` points at. Use `go test $(go list ./... | grep -v /tests/e2e)`, then `(cd prober && go test ./...)` and `(cd ui && go test ./...)`. E2E only via `make e2e-tests`, on purpose.
- `go vet` has known "copies lock value" warnings in `tests/e2e/utils_test.go`; not yours.
- CI (`pull_request.yml`): unit, integration, docs, helm, image builds with a Trivy scan (CRITICAL, unfixed ignored). E2E runs only with the `run-e2e` label, so CI never exercises a real cluster by default.
- `.trivyignore` holds CVE ignores with the reason and removal condition in comments. Keep that format.

## Code conventions

- Keep functions and methods to about 20 lines (REVIEW.md); split into focused helpers as you write, don't wait for review.
- Errors: `github.com/pkg/errors` (`Wrap`/`Wrapf`/`Errorf`), lowercase, no trailing punctuation. New code doesn't use `fmt.Errorf`.
- A bug fix comes with a test that fails on the old code. Tests for new controller logic go next to it (`*_test.go`); cross-component behavior goes in `tests/integration`.
- The operator reconciles on StatefulSet/CR events, not pod events. A state change that only shows up in pod readiness (e.g. a node leaving) needs an explicit `RequeueAfter`, otherwise the reconcile idles until something else changes.
- Prober readiness: a pod is Ready only if its own gossip status is `NORMAL` (JOINING/LEAVING/MOVING etc. are unready), so decommissioning and joining nodes are never counted as ready.

## Git and PRs

- Never push to `main`. Branch, push, open a PR. CI must be green; merging needs maintainer review.
- PR title goes into release notes, so make it a clear one-liner. Add `Resolves #N`, a label (`enhancement`, `bug`; CONTRIBUTING also lists `breaking-change`, which doesn't exist in the repo yet), and document upgrade steps if users must act.
- Note behavior changes (startup, scale up/down, decommission, upgrade) in the PR description, and ask the user before making one.
- Small, single-purpose PRs. Separate bugs found while testing get their own issue/PR.

## Working against the local cluster

- Dev cluster: kind cluster `cassandra` (nodes `cassandra-control-plane`, `-worker*`). Operator in `mr-cassop-system`, `test-cluster` in `cassop`. Images are `ghcr.io/cin/mr-cassop/*:dev`, loaded with `kind load docker-image --name cassandra` and `imagePullPolicy: Never`. Don't create a second kind cluster without asking.
- Install with the `local-install` skill; `test-cluster.yaml` is no-PVC, `test-cluster-pvc.yaml` is 5Gi PVCs (use PVC for upgrade tests, since no-PVC loses data on restart).
- Let rollouts finish on their own. Never restart Prober, Cassandra and Reaper together; don't `rollout restart` Cassandra to "speed up" a change. Rolling is one pod at a time, ~3 min per node.
- Dev secrets (`admin-secret`, `test-secret`) are dummy values. Never print passwords. The credentials the cluster actually uses are in the operator-managed `<cluster>-auth-active-admin` secret; `admin-secret` can be out of sync with it. Don't regenerate `admin-secret` on a rerun: a changed password triggers a live `ALTER ROLE`.
- `nodetool` / `cqlsh` run in the `cassandra` container of a `<cluster>-cassandra-<dc>-N` pod (`kubectl exec -c cassandra`); the `icarus` container is the sidecar, on port 4567.
- Do not delete cluster resources, secrets or namespaces you didn't create. Clean up what you did (test CRs, jobs, keyspaces, buckets).

## Gotchas

- Fresh installs go through a one-time StatefulSet migration to `OrderedReady` (`migrateToOrderedReady`). It must never delete a Cassandra pod; verify with pod UIDs or the API-server audit log when touching it.
- `CASSANDRA_NODE_PREVIOUS_IP` is injected from the `<cluster>-pod-ips` ConfigMap and becomes `-Dcassandra.replace_address_first_boot`. A stale entry can crash-loop a pod on its own IP ("Cannot replace_address ... doesn't exist in gossip", #160). Recovery: remove the pod's key from the ConfigMap, delete the pod (and its PVC if its data is stale).
- Backup/restore (Icarus):
  - Icarus ignores the Secret named by `spec.secretName`; the operator still requires it to exist. Credentials come from the AWS SDK default chain (IRSA on EKS). On kind, put a temporary `~/.aws/credentials` + `config` (with region) into each `icarus` container; they vanish when the container restarts. Never store real credentials in the repo or a long-lived Secret.
  - Use a bare `s3://bucket` for `storageLocation`; with a path prefix icarus 4.1.14 treated `bucket/path` as the bucket name.
  - Icarus request bodies use singular `keyspace` (not `keyspaces`). Running scrub/cleanup/upgradesstables on the same keyspace at the same time makes one fail ("Failed marking some sstables compacting").
  - Test with a real workload and compare row counts and aggregates before and after the restore. Delete test buckets afterwards.
- `count(*)` over a large table can hit server read timeouts; use keyed reads, aggregates with `CONSISTENCY ALL`, or `nodetool tablestats` instead.
- Quote globs in zsh (`grep 'cassandra-dc1-[0-9]'`, `--include='*.go'`) or they fail with "no matches found".
- Don't commit scratch artifacts: `*.out`, `local-values-*.yaml` are gitignored; keep temp files in a scratch dir, not the repo.
